# Standalone reader release

1. Verify existing repository/site identity before reuse. Otherwise create a dedicated project for this IP. Do not copy Signal Comics' production identifiers or news/field-note format into an unrelated story.
2. Build around the complete finished installment: clear reading entry, readable pages/panels, chapter navigation, cast context where useful, accessible transcripts and phone flow. Use actual accepted art. Keep production notes outside the narrative flow.
3. Read the available Sites skill and use its current source-save/build/deploy process when Sites is the selected host. An unavailable provider may justify a user-authorized alternative, never an invented success URL.
4. Run relevant build/type/lint checks and inspect desktop and phone reading in the browser. Verify panel order, text legibility, navigation, image loading, transcript access and overflow. Repair discovered defects. Record the actual viewport sizes and observed results.
5. Deploy with the recorded release audience, verify returned deployment state, then verify the live URL and intended installment. A saved version, source push, local preview or pending deployment is insufficient.
6. Archive masters and release derivatives with readback hashes at authorized destinations. Log evidence in Linear when available; otherwise save a ready-to-sync record with why, scope, acceptance, evidence and remaining risk.
