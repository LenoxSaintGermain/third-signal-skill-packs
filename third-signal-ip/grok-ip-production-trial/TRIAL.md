# What to give Grok

## Public workflow pack

Share this repository or `dist/grok-ip-production-trial.zip`. Start at `grok-ip-production-trial/PROMPT.md`. The bundle includes the real workflow, references, capture/ingestion validators. Optional desk state tooling remains in the repository under `publishing-desk`. It does not contain a reader application, cast, canon bible, credentials or hosting account.

## Private source attachment

Attach only one selected, authorized test IP package directly to the intended Grok session:

- `BRIEF.md`: premise, audience, one bounded installment, route and intended outcome.
- `CANON.md`: confirmed facts, proposed ideas, unresolved conflicts, character identity and costume/prop locks.
- Original reference images for the characters actually in the pilot; current accepted identities control older scene art.
- One source script or published comic plus its field note/research sources when applicable.
- `ASSETS.json`: relative paths, IDs, SHA-256, dimensions, parent references and acceptance/canon states. Include original binaries, not just links or contact sheets.
- `AUTHORITY.md`: creative scope, selected asset-use rights, accepted audience, deploy destination and spending ceiling. Existing user authority is evidence; do not manufacture owner approval.
- For a continuation, the last checkpoint and known rejected/superseded variants needed to prevent repetition.
- For Signal Stage only, access to the real runtime checkout, its version and working example. A library packager alone cannot deploy that harness.

Keep private sources out of the public skill repo. Provide provider credentials through the host's normal secure connection, never a prompt, ZIP or receipt. Do not grant every account merely to pass this test.

## Suggested first test

Use one four-panel alternate adaptation of a published comic, or one small original-IP scene with two characters. Keep it in a separate test project; never overwrite the canonical comic. Choose a scene with a visible constraint, a reversal and a clear final consequence. Use the same approved reference bytes across agents if comparing them; preserve each actual model/tool, settings and cost.

A standalone reader is the simplest first route. Test the Signal Stage harness after the comic artifacts pass. Motion is a later separate experiment, not a requirement for the comics trial.

## Acceptance

Score each dimension 0–2: 0 absent/failed, 1 partial, 2 verified.

1. Source honesty and provenance.
2. WIND situation: system operates, costs and changes the scene.
3. Character identity, costume and prop continuity across all panels.
4. Readable sequence and ending, understood without the field note explaining it.
5. Original art bytes, clean masters and readable lettering/transcript.
6. Reproducible package, hashes and resumable checkpoint.
7. Actual desktop and phone reader QA.
8. Deployment and live route/image checks at the authorized audience.

A full pass requires at least 14/16, no failed dimension and dimension 8 = 2. Private access must actually be private; an obscure public URL is not a private preview. Report a creative/package pass separately when hosting is unavailable. A self-score is preliminary until reviewed against the returned files and live result.

## Known lessons to carry forward

- Reference sheets control identity; an older approved action shot may contain superseded identity drift.
- Lock four-panel geometry, background topology, handedness and prop custody before rendering.
- Missing hands, pseudo-text and duplicated objects require upstream repair, not a flattering QA summary.
- Put the joke/reversal in the comic; field notes add evidence and invite interpretation, not rescue an unclear ending.
- News-based comics need dated primary sources. Distinguish reported facts, comic extrapolation and prediction.
- Every released item needs a stable addressable route or anchor, including archive entries. HTTP 200 alone does not prove a fragment exists or images loaded.
- Capture generated binaries immediately. Preserve unavailable tool metadata as unknown.
- Retry failed assets only; reconcile ambiguous submissions before spending again.
- For later motion: register characters if the provider truly supports it, isolate one keyframe per beat, specify targets/eyelines and bounded movement, download/review actual clips, then verify the saved timeline. A glow alone does not demonstrate a fictional mechanic.

## What this repository does not prove

The local deployment and archive infrastructure used for Signal Comics is not automatically available in Grok. Hosting, image generation, authenticated cloud access and the Signal Stage runtime are capability dependencies. The trial is specifically intended to measure those gaps as well as creative quality.
